# 注册登录

已实现 H5 邮箱密码注册、登录、退出、邮箱验证和密码找回。启动方法见 [启动文档](../README.md)，需求基线见 [第一版需求](mvp-requirements.md)。

## 使用流程

启动数据库后执行 `pnpm db:generate`、`pnpm db:migrate` 和 `pnpm dev`。打开 H5，点击「我的」→「登录 / 注册」。注册成功即登录并返回「我的」；刷新后会重新向服务端确认会话。退出后旧会话立即不可用。

邮箱去除首尾空格、转小写后判重，最长 254 个字符。密码按 Unicode 码点计算 8–64 个字符，不自动去除空格。系统生成初始昵称，资料编辑后续实现。

## 接口

| 方法与路径 | 请求 | 成功结果 |
| --- | --- | --- |
| POST /api/auth/register | JSON：email、password | 201，设置 Cookie，返回本人账号 |
| POST /api/auth/login | JSON：email、password | 200，设置新 Cookie，返回本人账号 |
| GET /api/auth/me | Cookie 会话 | 200，返回本人账号 |
| POST /api/auth/logout | Cookie 会话 | 204，撤销会话并清除 Cookie；重复退出仍成功 |
| POST /api/auth/email/request | 登录会话 | 202，发送邮箱验证链接；已验证账号无需重复发送 |
| POST /api/auth/email/verify | JSON：token | 200，确认邮箱归属 |
| POST /api/auth/password/forgot | JSON：email | 202，统一提示，不披露账号存在与否 |
| POST /api/auth/password/reset | JSON：token、password | 200，设置新密码、撤销所有会话并清除当前 Cookie |

账号响应为 `{ "user": { "id": "UUID", "email": "邮箱", "nickname": "昵称", "isEmailVerified": false } }`，仅本人认证接口包含邮箱。密码摘要、会话令牌和邮件令牌不在 JSON 中返回。错误状态：400 输入或链接无效、401 凭据或会话无效、403 来源不受信任、409 邮箱已注册、429 超出频率限制、503 发信失败。找回请求对不存在、禁用、冷却中或发送失败的账号均返回相同 202 提示；收到提示不代表邮件已送达。

POST 必须携带 `Origin`，且精确匹配 `CORS_ORIGINS`。非浏览器接口调试也需要设置该头；本地例如 `Origin: http://127.0.0.1:5173`。未来小程序和 App 的身份传输方式在平台适配时另行实现，不直接复用 H5 Cookie 方案。

## 会话与运行配置

- 密码使用随机盐和 scrypt（N=32768、r=8、p=1），比较时使用恒定时间比较。未知邮箱也执行密码校验，错误凭据和不可用账号采用统一错误消息。
- 会话采用 32 字节随机令牌，数据库只保存 SHA-256 摘要，有效期 7 天；每次读取检查有效期及用户禁用状态。成功注册或登录会替换当前浏览器旧会话，其他浏览器会话独立。退出删除当前会话。
- H5 使用 `HttpOnly`、`SameSite=Lax`、`Path=/api` Cookie，不将令牌写入 localStorage。生产 API **必须设置 `NODE_ENV=production` 并使用 HTTPS**，以启用 Secure Cookie；前端和 API 建议使用同源 `/api` 代理。生产站点域名必须写入 `CORS_ORIGINS`。
- 注册与登录合计按直连客户端 IP 限制为 15 分钟 10 次，邮件相关接口使用另一组相同额度，包括无效输入和失败请求；每个用户每类邮件另有数据库保存的 60 秒发送间隔。当前 IP 限流使用单进程内存，重启后清空，不信任 `X-Forwarded-For`；部署反向代理或多实例前需设计可信代理和共享限流。退出不占用额度。
- 数据库禁用字段已经参与认证检查；用户禁用管理界面尚未实现。未来禁用操作必须同时删除用户会话，避免恢复账号时旧会话恢复可用。
- 既有账号迁移后默认未验证，注册后从「我的」主动发送验证邮件。验证链接 24 小时有效；找回密码链接 30 分钟有效。令牌只保存 SHA-256 摘要，单次使用、区分用途；重发使同用途旧链接失效，邮件链接 GET 不会直接消费令牌，需在页面点击确认。重置密码同时确认邮箱归属、撤销所有设备会话和剩余邮件令牌；登录流程与重置使用相同用户行锁，避免旧密码在并发重置后继续创建会话。
- 未验证账号暂可登录查看自己的资料；内容发布尚未开放，后续需要验证邮箱的写操作应检查 `isEmailVerified`。后台管理员认证和完整账号风控仍待实现。

## QQ 邮箱配置

在 `apps/api/.env` 填写 `SMTP_HOST=smtp.qq.com`、`SMTP_PORT=465`、`SMTP_SECURE=true`、完整邮箱地址 `SMTP_USER`、SMTP 授权码 `SMTP_PASS` 和相同的发件地址 `MAIL_FROM`。使用授权码，不使用 QQ 登录密码；授权码只放本地配置或部署密钥中。SMTP 默认验证服务器证书，远程 587 端口会强制 STARTTLS，不允许降级为明文。

`PUBLIC_WEB_URL` 是邮件链接的前端地址，开发默认 `http://127.0.0.1:5173`，生产必须配置 HTTPS。默认地址仅能在运行项目的电脑打开；手机或其他电脑访问前需另行配置可达地址、开发监听和可信来源。不要根据请求 Host 或用户输入生成邮件链接。

SMTP 配置按需读取，配置缺失不影响健康检查和普通登录，发送验证邮件时会返回通用失败提示；可修改配置后重启 API。密码找回始终采用统一提示，避免通过状态码探测账号。

本地邮件测试使用 `docker compose --profile test-mail up -d mailpit`。Mailpit 只绑定本机且不向外部转发；测试邮件包含敏感链接，测试完成可执行 `docker compose --profile test-mail stop mailpit` 停止收件箱。无需改变你本机的 QQ 配置，Playwright 会为测试 API 单独覆盖 SMTP 环境变量。

## 验证范围

`pnpm verify` 覆盖密码加盐与空格/Unicode、输入边界、Cookie 解析及生产标志、来源校验、限流、类型与构建，以及已有仓库检查。

`pnpm test:integration` 使用真实 PostgreSQL，覆盖邮箱判重、并发注册唯一性、会话摘要存储、匿名访问、错误凭据、会话轮换、退出撤销、过期、禁用和双账号隔离。

`pnpm test:e2e` 覆盖 H5 注册、无效表单、重复邮箱、错误密码、刷新保持会话、HttpOnly、退出后旧会话不可用、浏览器会话隔离，以及外部返回地址被限制为站内页面。测试只清理本次随机账号，不删除现有用户。

邮件补充测试覆盖 SMTP 参数和 TLS、令牌用途隔离、过期、重发、并发单次消费、失败发信的令牌清理、重置后的旧密码失效与所有旧会话撤销，以及从 Mailpit 收到真实 SMTP 邮件并在 H5 中验证和重置的完整流程。
