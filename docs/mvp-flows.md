# 页面与验收流程

需求依据：[第一版需求](mvp-requirements.md)。路由为规划名称，后续以 uni-app 的 pages 配置落地。底部导航使用「发现、关注、发布、我的」，搜索从发现页进入；笔记和用户页面支持直接链接访问。

## 客户端页面

| 页面 | 建议路径 | 访问与主要操作 |
| --- | --- | --- |
| 发现 | /pages/discover/index | 游客可浏览；搜索入口、瀑布流、进入详情 |
| 关注 | /pages/following/index | 需要登录；关注作者内容、进入详情 |
| 搜索 | /pages/search/index | 游客可用；关键词输入、分页结果 |
| 登录注册 | /pages/auth/index | 邮箱密码、切换注册、成功后返回原操作页面 |
| 发布编辑 | /pages/note/editor | 需要登录；图片排序、标题正文标签、预览提交 |
| 笔记详情 | /pages/note/detail?id=... | 公开可读；点赞收藏评论、作者入口、举报 |
| 用户主页 | /pages/user/profile?id=... | 公开资料和公开笔记、关注、举报 |
| 关系列表 | /pages/user/relations?id=...&type=following | 关注与粉丝列表，进入用户主页 |
| 我的 | /pages/me/index | 游客显示登录入口；本人资料、笔记及审核状态、收藏、退出 |
| 编辑资料 | /pages/me/edit | 需要登录；头像昵称简介 |
| 我的收藏 | /pages/me/favorites | 仅本人可读；分页收藏列表 |
| 举报 | /pages/report/index?type=...&id=... | 需要登录；原因和补充说明 |

登录前保留可校验的站内目标页面，登录后返回；不接受任意外部跳转地址。不自动重放发布、评论等写操作，由用户重新确认提交。接口返回登录失效时清除失效状态，提示登录，并保留当前输入供返回后恢复；退出登录清除个人缓存。

## 管理后台页面

| 页面 | 主要操作 |
| --- | --- |
| 登录 | 管理员登录，不开放注册 |
| 用户管理 | 查询、禁用、恢复、查看处理原因 |
| 笔记审核 | 待审队列、内容预览、批准、驳回、隐藏、复核恢复 |
| 评论管理 | 查询、隐藏、恢复 |
| 举报处理 | 按待处理状态筛选、查看对象、记录处理结果 |
| 操作记录 | 按管理员、对象和时间查询 |

所有后台页面需要管理员身份。处理已删除对象时展示已删除状态，不尝试恢复。多个管理员并发操作时校验当前状态，避免覆盖更新。

## 端到端验收场景

以下场景是未来业务自动化测试与人工验收的依据，目前仅完成规划文档。每项都需要覆盖成功流程以及列出的关键异常。

### F01 账号与资料

覆盖：R01、R02。

游客浏览发现页 → 点击发布 → 注册账号 A → 返回发布页 → 修改资料 → 退出 → 重新登录。检查重复邮箱被拒绝、错误密码被拒绝、过期会话不可写、账号 B 无法修改 A 的资料，公开主页不泄露邮箱。

### F02 发布、审核与编辑

覆盖：R03、R04、R05、R10。

A 选择图片并排序 → 填写图文 → 预览 → 提交待审核 → 管理员批准 → 游客从发现页打开详情。检查超限图片、伪造格式、他人上传对象和重复提交。A 编辑后内容撤下并重新待审；驳回后 A 查看原因并修改送审；删除后旧详情不可读，关联媒体不可越权读取。

### F03 搜索与浏览

覆盖：R05、R06、R02。

游客输入中文关键词 → 打开搜索结果 → 查看详情 → 进入作者主页 → 加载下一页。检查空关键词、无结果、请求失败重试、游标分页不重复，以及隐藏或删除内容不在搜索、主页或发现页出现。

### F04 互动与收藏

覆盖：R07、R08。

B 登录 → 打开 A 的公开笔记 → 点赞、收藏、评论 → 刷新 → 从自己的收藏再次进入 → 删除自己的评论 → 取消点赞收藏。检查重复及并发操作、空白评论、脚本作为文本展示、A 无权删除 B 的评论、他人不能读取 B 的收藏；笔记隐藏后不能新增互动或泄露收藏内容。

### F05 关注

覆盖：R09。

B 关注 A → 进入关注页查看 A 的公开笔记 → 从关系列表进入主页 → 取消关注 → 刷新关注页。检查自关注被拒绝、重复关系不产生、数量不为负、无关注时有引导。

### F06 举报、隐藏和禁用

覆盖：R10、R11、R01。

B 举报笔记或评论 → 管理员处理举报并隐藏内容 → 游客访问旧链接及列表 → 管理员复核恢复 → 管理员禁用 B → B 使用旧会话写入被拒绝 → 恢复 B 后重新登录。检查普通用户无法调用后台接口、重复待处理举报不累积、审核原因和操作记录完整。

### F07 部署与恢复

覆盖：R12。

从干净环境安装并启动 → 执行迁移 → 初始化管理员 → 使用 A/B 账号跑通 F01 至 F06 → 备份数据库 → 在隔离测试环境恢复并核对记录与媒体引用。检查无真实凭据入库、日志无密码令牌、限流生效、客户端不暴露堆栈、生产构建和全部自动化检查通过。

## 交付阶段

| 阶段 | 可验证成果 | 对应场景 |
| --- | --- | --- |
| 工程基础 | 客户端调用服务端，数据库可连接，CI 可运行 | F07 的启动部分 |
| 账号资料 | 双账号可登录及修改资料 | F01 |
| 图文发布 | 图片上传、笔记管理、最小审核功能 | F02 |
| 浏览搜索 | 发现、详情、主页和搜索 | F03 |
| 社区互动 | 点赞收藏评论关注 | F04、F05 |
| 运营与部署 | 举报、管理、权限、备份和恢复 | F06、F07 |

测试应随功能开发增量补齐，每次交付执行全部已存在的自动化检查；页面状态需覆盖加载中、空数据、失败可重试、登录失效与无权限。H5 稳定后再为微信小程序及 App 制定平台专用验收清单。
